## 절대 규칙

1. **배포 확인은 쿼리 없는 경로나 HTML로.** 자산이 `immutable, max-age=31536000`이라
   배포 전에 `?v=` URL을 찌르면 **옛 파일이 1년짜리로 엣지에 박힌다.** 이미 한 번 사고 냄.
   ```bash
   until curl -sL https://galla.im/login.html | grep -q 'login.js?v=0901011'; do sleep 20; done
   ```
2. **파괴적 SQL은 반드시 `begin; … rollback;`** 또는 DO 블록 끝에 `raise exception`으로 되돌린다.
   지우기 전엔 **먼저 센다**(4,614행 사고 이력).
3. **마이그레이션 버전 중복 금지.** 오늘자 번호가 `20260901…`까지 차 있다. 겹치면 `db push`가 깨진다.
   직접 SQL로 적용했으면 `supabase_migrations.schema_migrations`에 기록도 넣어라.
4. **RLS PERMISSIVE는 OR로 합쳐진다.** 제대로 된 정책이 옆에 있어도 헐거운 것 하나가 전부를 무력화한다.
   이 함정으로만 결함 3건 나옴(정지 기능, 스토리지 쓰기, …).
5. **비율로 판정해라.** 5분 크론의 1회 실패는 2,016회 중 1회(0.05%)라 잡음이다.
   "실패 1건"과 "실패율 14%"는 완전히 다른 얘기다.
6. **검사가 헛돌지 않는지 확인해라.** 0건이 나오면 "막혔다"가 아니라
   "대상 자체가 없었나"를 먼저 확인한다(남의 DM 729행이 실재하는데 0으로 보이는지 확인하는 식).
