## 0. 먼저 — 이 목록으로 QA 할 때의 규칙

1. **로그인 계정을 적는다.** 심사계정(appreview@galla.im)인지 사장님 계정인지에 따라 보이는 게 다르다.
   게스트(비로그인)로도 한 번 돈다 — 로그인 유도가 제대로 뜨는지가 절반이다.
2. **웹·iOS·AOS 를 따로 센다.** 같은 버튼이 앱에서만 죽은 사고가 반복됐다
   (패스키 버튼 가림, SPA 여백 증발, 맛집 탭 4종).
3. **"눌러서 반응이 있었다"로 ✅ 하지 않는다.** 결과가 DB·화면에 남았는지까지 본다.
   과거 감사에서 `el.click()` 은 히트테스트를 건너뛰어 **덮여 있어도 통과**로 나왔다.
4. 안 되는 걸 찾으면 **재현 순서와 실측 숫자**를 메모 칸에 적는다.
5. ⚠️ **페인트가 멈춘 탭에서 잰 값은 믿지 마라 — 이 함정으로 결함 3건을 잘못 올렸다(0909).**
   백그라운드 탭은 `requestAnimationFrame` 이 발화하지 않고 레이아웃도 갱신되지 않는다.
   그래서 시트가 화면 밖(top=뷰포트 높이)에, 카운트업 숫자가 `0` 에 멈춰 **읽힌다**.
   **그러나 실사용자는 화면을 보므로 페인트가 일어나고, 그 순간 rAF 가 밀린 콜백을 실행한다** —
   즉 사용자에게는 정상이다. 판별법: `computer{action:"screenshot"}` 으로 페인트를 강제한 뒤 다시 재라.
   스크린샷 한 번에 `__raf` 가 0→1 이 되고 위치·숫자가 정상으로 돌아오면 그건 **결함이 아니다.**
6. ⚠️ **브라우저 패널이 숨겨져 있으면 페이지가 페인트되지 않는다** — CSS 트랜지션이 진행되지 않고
   IntersectionObserver 도 안 뜬다. 그래서 토스트가 `opacity:0` 으로, 바텀시트가 화면 밖(`y=871`,
   뷰포트 812)에 멈춘 채로 읽혀 **멀쩡한 기능이 결함으로 보인다**(0909 에 투표 잠금 안내를
   두 번 오판했다). 스크롤·무한로딩·애니메이션 판정은 패널을 띄운 상태에서만 한다.

- 앱 프로세스는 살아 있었다(`ps` 확인). 시뮬레이터 크래시 리포트 **0건**(`DiagnosticReports` 확인) — WebContent 프로세스 크래시는 아니다
- **재현 실패**: 같은 순서로 다시 하니 정상 렌더(13:36). 로그 스트림도 붙여봤지만 error/exception 라인 0건
- 남은 단서: WebKit 리소스 로그의 `resourceID` 가 39초 만에 4,142 → 28,354 로 뛴다(초당 수백 건). 다만 `resourceID` 는 WebContent 프로세스 전역 카운터라 이 페이지 것만은 아니다. 같은 페이지를 웹에서 29초 띄웠을 땐 리소스 **73건**뿐이라 대조가 안 된다(브라우저 창이 안 그려져 영상이 안 붙는 조건이라 비교가 공정하지 않다)
- **판정 보류.** 다시 나오면 그 자리에서 `log stream` 을 붙여 URL 까지 받는다

### 8-D. ❌ **결함(심사 위험) — 갈라캐시 안내 페이지의 앱 가드가 SPA 에서 돌지 않았다**

**앱에서 원화 가격표와 외부 결제수단이 그대로 보일 수 있었다** — App Store anti-steering 거절 사유.

- 구조: `products.html`(갈라캐시 안내·가격)은 웹 PG 심사용이라 **6티어 원화 가격표**와 「카카오페이·네이버페이·토스페이·페이코·삼성페이·애플페이」를 싣는다. 앱에선 이걸 감추고 「App Store 결제」 안내로 바꾸는 가드가 두 겹 있다 — ① 설정의 진입로 숨김(`js/settings.js`), ② **딥링크·뒤로가기 대비 페이지 자체 가드**
- 원인: ②가 **인라인 `<script>`** 였다. SPA 뷰 로더(`js/spa/view-loader.js`)는 `script[src]` 만 모아 실행하고 **인라인 스크립트는 버린다**(인라인 `<style>` 은 0830 에 살렸지만 스크립트는 여전히 src 만). products 전용 뷰 모듈도 없어 범용 폴백을 탄다 → **앱에선 두 번째 겹이 처음부터 없었다**
- 재현(웹 SPA 셸 `app.html` 에서 앱 판정 강제 `GALLA_isApp=()=>true` → `GALLA_nav('products.html')`), **수정 전 HEAD 파일로**:

타일·마커가 정상이었다(측정 규칙 §0-5).

**❌ 결함 발견·수정 — 보관 「맛집」 탭이 구조적으로 항상 비어 있었다**

찜을 눌러 `food_saves` 에 행이 생겨도 보관 맛집 탭은 「☆ 찜을 눌러보세요」만 떴다.

## 14-B. 크론 건강 점검 (2026-09-09, 서버)

**❌ 결함 — 5분마다 400 만 받던 죽은 크론을 껐다**

`fetch_article_thumbnail_job` 은 **24시간에 288회 실행되고 288회 모두 「succeeded」** 로 기록됐지만,
실제 HTTP 응답은 전부 **400 `{"error":"missing article_id or url"}`** 였다.
`fetch_article_thumbnail` 은 본문에 `article_id`·`url` 을 **필수**로 요구하는데 크론은 본문 없이 POST 한다.
게다가 대상 표 `news_articles` 는 **2026-01-12 이후 멈춘 옛 파이프라인**이다
(현재는 `news_articles_raw` 34만 행 + `galla_news` 가 살아 있다).

→ `cron.alter_job(active := false)` 로 **비활성화**(삭제 아님 — 되돌릴 수 있게).
배치용 `fetch_missing_thumbnails_job` 은 그대로 둔다. 현재 경로는 건강하다: 최근 24시간 갈라뉴스 269건 중
**hero_image 269건(100%)**.

**같이 확인한 것 — Authorization 없는 크론 34개는 정상이다.**
HTTP 호출 크론 53개 중 34개에 `Authorization` 헤더가 없어 [[크론 인증 함정]]을 의심했으나,
최근 6시간 응답에 **401 이 0건**이고 결과도 쌓인다(24시간 내 `travel_places` +2,721 · `food_places` +545).
`--no-verify-jwt` 로 배포된 함수들이라 헤더가 필요 없다 — **헤더 감사만으로 판정하면 오진한다.**

⚠️ 남은 관찰: `food_videos` 가 **5일째 정체**(마지막 2026-09-05, 총 28,358행)인데
